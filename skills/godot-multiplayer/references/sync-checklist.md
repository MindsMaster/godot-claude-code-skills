# 同步检查表

新增一个要联机的内容时逐项过。

## 新增技能或怪物行为

| 检查 | 漏掉时的现象 |
|---|---|
| 攻击动作和受击动作有同步路径 | 客户端怪物停在原地，没有起手就出伤害 |
| 预警圈 范围指示 法阵有同步路径 | 主机看到预警，客户端直接掉血 |
| 隐身 遁地 现身这类可见性走状态 | 主机已隐藏，客户端还看得见它在滑动 |
| 只在权威端生成的节点有复制方式 | 主机有实体，客户端节点数是 0 |

## 新增实体

| 检查 | 漏掉时的现象 |
|---|---|
| 位置 朝向 缩放在进入复制之前写好 | 客户端在原点生成 |
| 生成包带上外观参数 | 客户端显示成默认场景或默认颜色 |
| 全量状态里能列出它 | 后加入者看不到 |
| 销毁后全量状态能表达它已不存在 | 预置物在后加入者那边复活，碰撞也在 |
| 弹道逻辑用到的字段都进初始状态 | 收束 回旋弹在客户端直飞，和命中位置对不上 |

## 新增请求

| 检查 | 漏掉时的现象 |
|---|---|
| 主机取发送方身份，并校验在场 存活 距离 | 已离开的玩家还能操作 |
| 扣费请求带版本号或请求 id，发出后禁用按钮 | 一个往返内连点两次扣两次 |
| 失败和超时都有回执并解锁界面 | 面板永久锁死 |
| 回执判断不依赖只有成功才带的字段 | 超时结果被当成无关消息丢弃 |
| 改变校验版本的操作要把新版本推给客户端 | 下一个请求被判过期，反复重试都失败 |

## 新增奖励或全队效果

| 检查 | 漏掉时的现象 |
|---|---|
| 遍历所有玩家，不写本地玩家 | 只有主机拿到 |
| 主机专属交互不要默认复用到全队设施 | 客户端看不到交互提示 |
| 统计按稳定玩家 id，不按连接 id | 重连后结算只剩新连接的数据 |

## 离线与重连

| 检查 | 漏掉时的现象 |
|---|---|
| 局结束时离线记录也清局内数据 | 重连玩家把上局装备带进下一局 |
| 重连落点在所在房间已销毁时回退到入口 | 用旧坐标生成在地图外 |
| 死亡态进全量状态并能驱动死亡流程 | 血量是 0，但没有提示也不能复活 |
| 加入期间角色处于切换保护 | 加载时角色已在房间里，可被攻击 |
| 最后一个玩家断线时房间按无人处理 | 房间在后台继续推进 |
| 主动离开和被断开走同一份清理 | 主动离开后局内状态带回单机 |

## 切换房间

| 检查 | 漏掉时的现象 |
|---|---|
| 批量传送检查每个玩家的返回值 | 切换中的玩家被留下，流程还报成功 |
| 准备中的房间不被无人冻结 | 进门流程永久等待 |
| 换房时移动状态在两端保持一致 | 冷却只有一端留着 |
